# 六条工作流实战人工验收清单

这份清单供学习者完成自动化检查后，亲自判断课程是否真的可跟做。它不替代测试，也不把 Agent 的完成陈述当成 `Human Accepted`。

## 使用方式

1. 使用一个全新的浏览器窗口，清除本地学习进度，按当前线上课程进入目标路线。
2. 记录浏览器、屏幕宽度、日期、起始 Tag、参考 Tag 和实际执行的命令。
3. 每条路线先完成自动化检查，再执行下面的人工观察。
4. 对每一项填写：通过、失败、未执行或不适用，并附截图、命令输出、页面行为或用户决定。
5. 最后分别填写 `Automated Verified`、`Spec Reviewed`、`Human Accepted` 和 `Knowledge Reconciled`；四个状态不能互相代替。

- [ ] 空状态能说明当前没有任务，主按钮明显且能用键盘聚焦。

## Story 05：复杂 Bug 诊断

前置：先在 `story-05-start-r1` 上运行预期失败的复现；参考实现为 `story-05-example-r2`。

- [ ] 旧版本能按“拖动到已完成 → 刷新”稳定复现状态丢失。
- [ ] 观察到保存请求、响应和刷新结果；没有只依据页面乐观状态判断成功。
- [ ] 根因假设与源码、Network 或数据库证据对应；一次只验证一个假设。
- [ ] 修复后使用同一回归测试证明红转绿；断言没有被放宽，等待没有被无故延长。
- [ ] 按原始用户路径重新拖动、等待保存、刷新并确认状态保持。
- [ ] 人工记录仍区分本地修复已验证与其他部署环境尚未验证。

## Story 06：安全重构

前置：在 `story-06-start-r1` 上先运行行为测试基线；参考实现为 `story-06-example-r3`。

- [ ] CodeGraph 结果与关键源码、调用者和测试入口核对过，没有把静态图谱当成全部真相。

- [ ] Review 比较了调用方接口、依赖方向和行为证据；Retro 建议有适用范围。
