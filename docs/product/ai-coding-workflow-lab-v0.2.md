## 1. 产品定位

**展示名称：AI Coding Workflow Lab**  
**中文名称：AI 编程工作流实验室**  
**副标题：面向 AI Coding Agent 的工程方法、工作流与实战**

本项目聚焦如何使用 AI Coding Agent 参与规范化软件工程，不覆盖泛 AI、模型训练、RAG 或 Agent 平台等宽泛主题。

产品目标：帮助开发者理解工程方法、选择适当工作流、使用不同方法论工具，并通过真实任务完成可验证的开发实践。

Matt Pocock Skills + CodeGraph 是第一套正式实践体系，不是平台永久绑定的唯一工具。未来可以加入 Superpowers、OpenSpec、Spec Kit 等，但必须先经过研究和课程设计。

## 2. 顶层信息架构

- 任务入口：从真实开发场景开始，进入对应工作流实战详情。
- 01 需求与架构：保留现有 7 个知识主题。
- 02 开发与交付：保留现有 8 个知识主题。
- 03 质量与演进：保留现有 7 个知识主题。
- 04 工作流实战：新增工作流方法论实践区。第一套方法论为 Matt Pocock Skills + CodeGraph，包含六条实战路线。

01～03 是相对工具中立的工程知识课程；04 展示特定方法论如何将这些知识组织成可执行流程。

## 3. 内容领域模型

必须区分三个独立概念：

### Scenario（工程场景）

描述真实业务问题、角色、当前状态、目标和约束。场景本身不绑定某个方法论。

### Playbook（工作流实践路线）

描述使用某一套方法论解决一个工程场景的具体方式，包括工作流判断、命令、提示词、Agent 预期行为、工件、人工决策、异常分支和验收。

### Knowledge Lesson（知识主题）

解释工程方法、机制、原则和技术背景。Playbook 可以引用一个或多个知识主题。

当前第一版是六个 Scenario 对应六个 Matt Playbook；数据模型应允许未来同一 Scenario 对应 Matt / Superpowers 等不同 Playbook，但不提前实现复杂插件系统。

### Methodology Pack（方法论包）

例如 Matt Pocock Skills + CodeGraph、Superpowers。一个方法论包拥有多条 Playbook，并说明上游来源、版本、设计哲学和适用边界。

## 4. 04 工作流实战：第一套方法论

方法论包：**Matt Pocock Skills + CodeGraph**

课程名称、Skill 名称和调用权限必须以当前上游仓库核实。六条路线是本实验室针对常见工程任务设计的教学工作流，不宣称它们是 Matt 上游官方定义的六条固定流程。

| 编号 | 工作流路线 | 真实场景 | 核心学习目标 |
|---|---|---|---|
| 01 | 快速修改 | 优化任务看板空状态页面 | 明确小任务直接实施，避免过度流程化 |
| 02 | 需求探索 | 设计任务逾期提醒 | 用 Grill 发现真实需求；此故事以需求确认结束，不擅自编码 |
| 03 | 常规功能开发 | 开发任务指派与成员协作 | Grill（必要时）→ Spec → Tickets → Implement → TDD / Review → 验收 |
| 04 | 大型架构 | 单团队任务看板升级为多团队 SaaS | Wayfinder 先解决未知决策，再 Research / Prototype、ADR、Spec、Tickets 和实施 |
| 05 | 复杂 Bug 诊断 | 拖动任务卡片后刷新，状态又恢复原样 | 稳定复现、最小化、假设验证、回归测试和原始场景复测 |
| 06 | 架构重构 | TaskService 职责过载 | CodeGraph 探索、架构机会分析、用户选择、小步行为保持重构与 Retro |

## 5. 每条 Playbook 的统一教学结构

每条实战路线必须包含以下八个教学章节：

1. **真实场景与业务背景**：产品是什么、用户是谁、当前状态、遇到什么问题、要达到什么结果。
2. **工作流选择与原因**：为什么选这条路线；何时适用、何时不适用；为什么不选其他路线。
3. **开发准备**：项目起始版本、环境要求、Skill 安装、项目上下文和 CodeGraph（如需要）。
4. **逐步执行**：每阶段给出准确的用户命令（若有）、完整可复制 Prompt、执行顺序和注意事项。
5. **Agent 预期行为**：说明 Agent 应先做什么、应提出什么问题、应该读取什么，不应擅自做什么。
6. **工件检查与交接**：展示预期文件或记录的真实示例、检查清单和进入下一阶段的条件。
7. **异常与人工决策**：展示至少一个真实中间问题、错误路径、暂停条件和用户决策点。
8. **最终验收与复盘**：自动化证据、规格符合性、人工验收、知识同步和完成状态。

每个执行阶段至少有：用户要做什么；命令 / 操作（区分 Slash Command、自然语言指令、shell 命令和 MCP 工具）；完整 Prompt；Agent 预期行为；预期产物；检查清单；下一步交接条件；事实来源或教学建议标记。

不能只放一个“复制 Prompt”按钮。初学者需要知道为什么执行、Agent 应该如何响应、结果应该长什么样、怎样判断可以继续。

## 6. Skill 调用教学规则

每个步骤必须区分：用户主动调用的 Skill / Slash Command；可由 Agent 按需调用的辅助 Skill；外部工具或 MCP（如 CodeGraph）；普通 shell 命令；人工确认节点。

不能把每个 Skill 都写成必须由用户逐一输入的命令。Matt 上游 frontmatter 中的 disable-model-invocation、当前宿主的安装方式和调用界面是判断依据。若不同宿主的命令形式不同，课程要说明宿主差异，不给出未经核实的统一命令。

/setup-matt-pocock-skills 是每个教学项目的一次性初始化步骤。为降低新手门槛，演示项目默认建议选择 Local Markdown tracker；如使用 GitHub Issues，必须先确认 gh 登录与仓库权限。

## 7. 配套教学项目：Team Task Board

建议独立仓库：shuge-x/ai-coding-workflow-demo（需由仓库所有者先创建，再授权 GitHub 集成访问）。

这是一个简单、真实、可运行的团队任务看板，用来承载六条实战路线。它不是另一个大型产品。

### 初始业务语言

- Project：项目。
- Task：任务。
- User：用户。
- Member / Membership：项目成员及成员关系。
- Due date：任务截止时间。
- Reminder：提醒。

初始版本只保留理解六条路线所需的最小领域，不一开始引入复杂组织、Runtime 或容器概念。

### 推荐技术栈

- Next.js App Router + React + TypeScript：一个仓库承载 UI 与服务端能力。
- Tailwind CSS：快速构建清晰 UI。
- Prisma + SQLite：初学者无需安装和维护数据库服务；后续架构故事再研究迁移到 PostgreSQL 的必要性。
- Vitest + Testing Library：快速单元 / 组件反馈。
- Playwright：关键用户旅程和真实浏览器验收。
- Node.js LTS + npm：降低本地启动门槛。

推荐栈是教学项目的实施选择，不是所有 AI Coding 项目的通用标准。

### 六个故事的起始状态

每条故事必须从明确、可复现的起始版本开始，不要求学生先完成前一个故事：

- 01：空任务看板，空状态样式和引导不完善。
- 02：现有任务具备截止日期概念，但逾期提醒规则未定义；只做需求探索，不要求实现。
- 03：已有项目和任务基础功能，尚无完整任务指派与协作体验。
- 04：单团队 / 单项目边界明确，尚未支持多团队；重点是架构决策和迁移路线。
- 05：提供一个确定可复现的拖拽状态持久化缺陷，作为诊断练习。
- 06：提供可运行但职责过载的 TaskService，配有行为测试，作为安全重构练习。

每条故事使用独立 tag 或分支基线，避免一个故事的修改污染另一个故事的起始环境。解决方案可提供独立参考分支，但不默认在初学者主路径中展示答案。

## 8. 页面与路由

- 首页任务入口展示六个真实开发故事。
- 顶部增加 04 工作流实战，显示当前方法论包和六条路线。
- 首页故事卡与 04 目录中的同一条路线必须进入同一个 Playbook 详情路由、读取同一数据源、共享同一学习进度。
- Playbook 详情复用现有 K8s 风格三栏学习工作台，但内容结构按实战教学设计。
- 01～03 原有 22 个知识主题保留，页面和学习进度不应被 04 破坏。
- Playbook 与 Knowledge Lesson 双向关联：从实战阶段可跳到知识主题；从知识主题可进入相关实战。
- 当前仅实现 Matt 方法论包；其他方法论采用同一数据模型预留，不建立空白课程或复杂插件注册机制。

## 9. 质量与验收标准

- 初学者不需要先理解 Workspace / Runtime 等复杂业务词汇即可进入实战。
- 每条路线都能回答：我遇到什么问题、为什么选这条流程、我输入什么、Agent 应做什么、我得到什么、如何检查、何时停下来。
- 所有命令和 Skill 调用方式有上游依据；区分用户调用与 Agent 调用。
- 每条路线至少有一个可展示的真实工件示例和一个错误 / 异常教学点。
- 六条路线从教学项目的固定起始版本出发，操作可复现。
- 首页与 04 目录共用 Playbook 路由和数据源。
- 保留 01～03 全部知识课程。
- Chromium 自动化覆盖导航、Playbook 路由、阶段切换、Prompt 复制、知识跳转和进度持久化。
- 对 Story 05 的 seeded bug，必须有自动化测试先红、修复后绿的证据；对 Story 06，重构前后行为测试保持通过。

## 10. 实施边界

本轮不引入 Superpowers 课程，不创建复杂的通用插件框架，不重写 01～03 的内容，不把六条路线写成上游官方工作流。

先把 Matt Pocock Skills + CodeGraph 的六条路线和 Team Task Board 教学项目做扎实。未来新增方法论时，通过新增 Methodology Pack / Playbook 数据接入，共享 Scenario、Knowledge Lesson 和工作台组件。
